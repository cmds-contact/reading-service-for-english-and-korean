# Claude Code를 위한 스킬 구축: 절차적 지식 자동화하기

스킬을 통해 팀의 워크플로우, 스키마, 비즈니스 로직을 Claude Code가 자동으로 불러오는 재사용 가능한 지침으로 패키징하는 방법을 알아보세요.

[Claude Code](https://www.claude.com/product/claude-code)에게 회사 데이터 웨어하우스 쿼리를 도와달라고 요청하면, 표준 SQL 패턴과 모범 사례를 제안할 것입니다. 제안 자체는 타당하지만, 그것은 *여러분의* 패턴이 아닙니다. Claude는 여러분의 테이블 구조, 비즈니스 용어, 또는 어떤 메트릭에 정확성을 위해 특정 필터가 필요한지 알지 못합니다.

Claude Code가 이러한 정형화된 제안을 생성하는 이유는 매 대화를 팀의 제도적 지식에 대한 접근 없이 새롭게 시작하기 때문입니다. 여러분의 데이터 문서는 위키, 스프레드시트, 그리고 암묵적 지식에 흩어져 있지만, Claude는 쉽게 접근할 수 없습니다.

[스킬](https://www.claude.com/blog/skills)은 Claude에게 여러분의 특정 워크플로우를 가르치는 모듈식 패키지를 제공함으로써 이를 해결합니다. Claude Code에 설치하거나 [Claude.ai](http://claude.ai)에서 활성화하면, 대화 중 관련 작업이 나타날 때 Claude가 자동으로 이를 참조합니다. 스킬을 AI가 여러분의 팀과 정확히 같은 방식으로 작업하도록 훈련시키는 전문화된 온보딩 문서라고 생각하세요.

이 글에서는 효과적인 스킬의 필수 구성 요소와 일반적인 모범 사례를 포함하여 Claude Code용 맞춤 스킬을 구축하는 방법을 공유합니다.

## AI에 제도적 지식이 부족할 때

팀은 데이터에 대한 힘들게 얻은 지식을 축적해왔습니다. 여러분은 어떤 테이블이 신뢰할 수 있는 소스인지, 왜 특정 필터가 항상 적용되어야 하는지, 그리고 상황에 따라 수익이 어떻게 다르게 계산될 수 있는지 알고 있습니다. 하지만 Claude는 이전 세션의 컨텍스트를 유지하지 않습니다.

팀의 데이터 플레이북을 공유할 방법이 없으면, 프롬프팅을 통해 같은 세부 사항을 반복해서 설명하게 됩니다. 스킬을 사용하면 그 전문 지식을 Claude Code가 자동으로 발견하고 사용할 수 있는 것으로 패키징할 수 있습니다.

## 스킬이 지식 격차를 해결하는 방법

스킬은 점진적 공개를 통해 Claude Code에 절차적 지식에 대한 접근을 제공하며, 컨텍스트 창을 가득 채우는 대신 필요할 때만 정보를 계층적으로 공개합니다.

작동 방식은 다음과 같습니다: Claude는 항상 사용 가능한 스킬의 가벼운 인덱스(이름과 설명, 각각 약 100단어)를 봅니다. 수익 데이터를 분석해달라고 요청하면, Claude는 데이터 웨어하우스 SQL 스킬이 적용됨을 인식하고 해당 지침을 로드합니다. 특정 테이블에 대한 상세 문서는 실행 중 필요할 때만 로드됩니다.

이 설계는 포괄적인 지식과 제한된 컨텍스트 사이의 근본적인 긴장을 해결합니다. 수십 개의 테이블 정의와 여러 페이지의 비즈니스 로직 문서로 스킬을 구축할 수 있지만, Claude는 현재 쿼리와 관련된 것만 로드합니다.

## 스킬의 구조

모든 스킬은 인간의 유지보수와 AI의 소비 모두를 위해 설계된 특정 구조를 따릅니다. 데이터 웨어하우스 스킬이 어떻게 구조화되는지 살펴보겠습니다.

그 설명이 Claude가 스킬을 로드할 시점을 결정합니다. 누군가 "지난 분기 수익이 얼마였나요" 또는 "세그먼트별 고객 이탈률을 보여주세요"라고 말하면, Claude는 이 스킬이 적용됨을 인식합니다.

마크다운 본문에는 점진적 공개를 위해 구성된 실제 지침이 포함됩니다:

SKILL.md가 상세 문서를 위한 참조 파일을 가리키면서 높은 수준의 워크플로우 가이드와 중요한 비즈니스 로직을 제공하는 방식에 주목하세요.

**참조: 온디맨드 문서**

`references/` 디렉토리에는 필요할 때만 Claude가 로드하는 상세 문서가 포함됩니다. ACME의 `references/finance.md`는 다음과 같이 보일 수 있습니다:

- **테이블 스키마**: `monthly_revenue` 및 `arr_metrics`와 같은 주요 테이블의 열 이름, 데이터 유형 및 설명
- **표준 필터**: 항상 적용되어야 하는 WHERE 절(예: 테스트 계정 제외, 완료된 기간만 사용)
- **메트릭 정의**: 정확한 공식으로 ARR, 실행률 및 기타 비즈니스 메트릭을 계산하는 방법
- **일반적인 쿼리 패턴**: "고객 세그먼트 및 지역별 수익" 또는 "시간에 따른 ARR 추세"와 같은 빈번한 요청을 위한 바로 적용 가능한 SQL 스니펫
- **엣지 케이스**: 한 테이블을 다른 테이블 대신 사용해야 하는 경우, 또는 명명 규칙이 일치하지 않더라도 JOIN에 일반적으로 사용되는 열과 같은 알려진 특이사항

각 참조 파일은 수천 단어가 될 수 있지만, 사용자는 실제로 필요한 것에 대해서만 컨텍스트 비용을 지불합니다.

기억해야 할 핵심 원칙: 정보는 SKILL.md 또는 참조 파일 중 하나에만 있어야 하며 둘 다에 있어서는 안 됩니다. 따라서 SKILL.md는 높은 수준의 지침으로 간결하게 유지하고 상세한 사양은 참조에 넣으세요.

**스킬 vs CLAUDE.md**

스킬과 CLAUDE.md 파일 모두 Claude에게 컨텍스트를 제공하지만, 다른 목적을 수행합니다. CLAUDE.md는 항상 Claude의 컨텍스트에 로드됩니다. 이것은 저장소에 단일 마크다운 파일로 존재하는 프로젝트별 가이드(코딩 규칙, 로컬 워크플로우, 일반적인 명령어)를 위한 것이며, Claude Code에서만 작동합니다.

스킬은 점진적 공개를 사용하여 관련될 때만 로드되며, 모든 Claude 플랫폼(claude.ai, Claude Code 및 Claude API)에서 작동합니다. 컨텍스트 관리 이점 외에도, 스킬은 마크다운뿐만 아니라 실행 가능한 코드와 참조 파일을 포함할 수 있습니다. 이는 데이터 웨어하우스 스키마, 회사 디자인 표준 또는 도메인 전문 지식과 같이 프로젝트에 걸친 실질적이고 재사용 가능한 지식에 이상적입니다.

## 첫 번째 스킬 구축하기

터미널 또는 IDE에 Claude Code를 설치하는 것으로 시작하세요:

그런 다음 [skill-creator 스킬](https://support.claude.com/en/articles/12599426-how-to-create-a-skill-with-claude-through-conversation)을 포함하는 Claude Code [플러그인](https://github.com/anthropics/skills/blob/0f77e501e6506235956d953cd2d7a2a4aa9ba133/.claude-plugin/marketplace.json#L24-L42)을 추가하세요. 이제 첫 번째 후보를 식별하세요. 최고의 스킬은 다음과 같은 특성을 공유합니다:

- **교차 저장소 관련성**: 여러 프로젝트에 적용되는 지식
- **다중 대상 가치**: 기술적 사용자와 비기술적 사용자 모두 혜택을 받음
- **안정적인 패턴**: 매 커밋마다 변경되지 않는 절차

데이터 웨어하우스 쿼리, 내부 플랫폼 문서화 및 회사 전체 표준은 모두 훌륭한 스킬이 됩니다.

Claude는 여기서 문서화 파트너로도 역할을 할 수 있습니다. 워크플로우를 대화체로 설명하는 것으로 시작하세요:

Claude는 이 과정에서 워크플로우에 대한 세부 정보를 수집하기 위해 명확한 질문을 할 것입니다: 주요 테이블은 무엇인가요? 어떤 비즈니스 용어가 정의가 필요한가요? 어떤 필터가 항상 적용되어야 하나요? 이 추출 과정은 스킬의 효과에 중요한 지식을 표면화합니다.

도메인의 개요를 잡으면, Claude가 SKILL.md를 구조화하고 참조 파일을 구성하는 것을 도와줄 것입니다. 스킬을 사용하면서, 누락된 것을 발견할 때마다 더 많은 참조 파일을 추가할 수 있습니다.

### 스킬 저장 및 공유

스킬은 로컬 머신에 저장되어 업데이트 시기와 방법을 완전히 제어할 수 있습니다. 팀과 스킬을 공유할 준비가 되면, 워크플로우에 따라 여러 옵션이 있습니다:

- **Zip 파일:** 빠르고 비공식적인 협업을 위해 팀원들과 직접 스킬을 공유
- **내부 버전 관리 저장소:** 조직이 코드와 함께 승인되고 유지 관리되는 버전에 접근할 수 있는 중앙 집중식 저장소에 스킬 호스팅
- **Git 저장소:** 전체 커밋 히스토리와 브랜치 관리와 함께 코드와 함께 스킬 버전 관리
- **플러그인 번들:** 팀 전체에 쉽게 배포할 수 있도록 스킬을 Claude Code 플러그인으로 패키징

팀이 이미 작업하는 방식에 맞는 접근 방식을 선택하세요. 강력한 Git 워크플로우를 가진 팀은 종종 저장소 기반 공유를 선호하고, 공식적인 도구 표준이 있는 조직은 플러그인 번들이나 중앙 집중식 스킬 저장소에서 혜택을 받을 수 있습니다.

## 실제 구현 패턴

다음은 스킬이 실제로 작동하는 것을 보여주는 커뮤니티의 예시입니다:

[Playwright 스킬](https://github.com/lackeyjb/playwright-skill): Claude가 Playwright를 사용하여 브라우저 자동화를 즉석에서 작성하고 실행할 수 있게 합니다. Claude에게 웹페이지를 테스트하거나, 폼이 올바르게 작동하는지 확인하거나, 스크린샷을 캡처하도록 요청하면, Claude가 코드를 작성하고, 실행하고, 수동 설정 없이 결과를 반환합니다.

[웹 자산 생성기 스킬:](https://www.reddit.com/r/ClaudeAI/comments/1ocm1if/built_a_claude_code_skill_that_completely/) 로고, 텍스트 또는 이모지에서 파비콘, 앱 아이콘 및 소셜 미디어 이미지를 생성합니다. Claude에게 스타트업용 파비콘이나 블로그용 Open Graph 이미지가 필요하다고 말하면, 프로젝트에 바로 사용할 수 있는 적절한 크기의 자산을 생성합니다.

이 [스킬 마켓플레이스](https://skillsmp.com/)는 영감을 줄 수 있는 더 많은 예시를 공유합니다. 자동화된 테스트 및 데이터 시각화부터 코드 리뷰 및 도메인 이름 브레인스토밍에 이르기까지 Claude가 할 수 있는 것을 확장하는 커뮤니티 구축 스킬을 탐색하세요.

## Claude Code와 스킬 시작하기

스킬을 사용하면 팀과 플랫폼 전반에 걸쳐 작동하는 제도적 지식을 인코딩할 수 있습니다. 절차, 용어 및 비즈니스 로직을 스킬로 캡처함으로써 확장 가능한 조직적 메모리를 만들 수 있습니다. 새로운 분석가는 첫날부터 올바르게 데이터를 쿼리하고, 데이터 과학자는 같은 테이블 관계를 설명하는 것을 멈추고, 비즈니스 사용자는 정확한 메트릭을 셀프 서비스할 수 있습니다. 오늘 [Claude Code](https://www.claude.com/product/claude-code)에서 첫 번째 스킬을 구축하세요.
